# MITASAI CASHER

学園祭の模擬店向けに、シンプルで使いやすいレジ Web アプリを用意しました。ブラウザだけで動作し、商品管理から会計・売上の Excel エクスポートまで完結します。

## 使い方

1. [三田祭レジ](https://yushi512.github.io/mitasai_casher/) をブラウザで開きます。ローカルでは `index.html` を開いて使うこともできます。
2. 商品カードの `＋/−` ボタンで数量を調整し、割引を選択して `会計` を押すと、その会計情報がブラウザに保存されます。
3. 売上 Excel が必要になったタイミングで、管理画面の「手動でエクスポート」から全会計データをまとめてダウンロードできます。
4. Googleスプレッドシートに記録する場合は、以下の初回設定後、**レジのメイン画面上部「売上の記録先」**にURLを貼り付けて保存します。

## Googleスプレッドシートへの自動記録

レジ画面で記録先のGoogleスプレッドシートURLまたはIDを指定できます。Googleスプレッドシートはオンラインのファイルなので、ファイルのアップロードは不要です。

### GitHub Pagesでの初回設定

1. 記録先のスプレッドシートを作成するか、既存のファイルを用意します。URLの `https://docs.google.com/spreadsheets/d/ここがID/edit` の部分からIDをコピーします。シートを一般公開する必要はありません。
2. [Google Apps Script](https://script.google.com/) で新しいプロジェクトを作成し、このリポジトリの [`apps-script/Code.gs`](apps-script/Code.gs) をコードエディタに貼り付けて保存します。
3. 左側の「プロジェクトの設定」→「スクリプト プロパティ」で次の2つを追加します。

   | プロパティ | 値 |
   | --- | --- |
   | `MITASAI_TOKEN` | パスワード生成機能などで作った32文字以上のランダムな接続用トークン |
   | `MITASAI_SPREADSHEET_IDS` | 記録を許可するスプレッドシートID。複数ある場合は半角カンマで区切る |

4. 右上「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」を選びます。「次のユーザーとして実行」は**自分**、「アクセスできるユーザー」は**全員**に設定してデプロイし、Googleの権限確認を完了します。実行者は記録先の編集権限を持っている必要があります。学校などの管理対象アカウントで「全員」が許可されない場合、この方式は利用できません。
5. 発行された末尾が `/exec` のウェブアプリURLをコピーします（`/dev` は使いません）。`doPost` をエディタから直接実行する必要はありません。
6. GitHub Pagesのレジを開き、画面上部「売上の記録先」でスプレッドシートURLを入力します。「初回のGoogle連携設定」にウェブアプリURLと接続用トークンを入力し、「自動記録を有効にする」にチェックして「接続を確認して保存」を押します。接続できたときだけ設定が反映され、保存したファイル名とリンクが表示されます。
7. 少額のテスト会計を1件行い、指定したファイルの **`MitasaiSales`** タブに追記され、未送信件数が0になることを確認してください。

ウェブアプリURLだけでは書き込めません。接続用トークンと記録先IDの許可リストでアクセスを制限しています。トークンはレジ利用者と共有する秘密情報です。公開リポジトリには実際のトークンを書かないでください。スクリプトのコードを更新した場合は、「デプロイを管理」から新しいバージョンを選んで更新します。

### GitHub PagesやローカルHTMLで記録先を変更する

1. 新しい記録先IDを、Apps Scriptの `MITASAI_SPREADSHEET_IDS` に追加します（プロパティ変更だけなら再デプロイ不要）。実行者がそのファイルを編集できることも確認します。
2. レジ画面のURL欄を変更し、「接続を確認して保存」を押します。接続に成功すると保存され、以降の会計から新しいファイルへ記録されます。

記録先を変更しても、過去の会計は移動・再送しません。未送信の会計は**会計時の記録先**を保持するため、元のURLとウェブアプリURLを設定し直してから「未送信の会計を再送」を押してください。「自動記録を有効にする」のチェックを外して保存すると、端末への保存のみになります。

### 別の公開方法としてApps Scriptを使う場合

この構成ではウェブアプリの `/exec` URLからレジ画面が開きます。レジ利用者はGoogleにログインし、自分が編集できるスプレッドシートを記録先に選べます。

1. リポジトリのルートで `node apps-script/build.cjs` を実行します。`dist/apps-script/` に `Code.gs`、`Index.html`、`appsscript.json` が生成されます。
2. [Google Apps Script](https://script.google.com/) でプロジェクトを作成します。既定のコードファイルを `Code.gs` の内容で置き換え、HTMLファイル `Index` を作成して `Index.html` の内容を貼り付けます。プロジェクト設定でマニフェストの表示を有効にし、生成した `appsscript.json` の内容を貼り付けます。
3. 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」で、**アクセスしているユーザーとして実行**を選びます。アクセス範囲は一人で使う場合は「自分のみ」、共同利用の場合はメンバーがログインできる範囲を選びます。共有スプレッドシートは各メンバーに編集権限を付けてください。
4. 発行された `/exec` URLを開き、Googleの権限確認を完了します。レジ画面上部の「売上の記録先」にスプレッドシートURLを貼り、「接続を確認して保存」を押します。編集権限を確認できるとファイル名が表示され、必要に応じて `MitasaiSales` タブと見出しが作成されます。
5. テスト会計を1件行い、指定したファイルに売上が追記されて未送信件数が0になることを確認します。記録先の変更も同じ画面でできます。

記録先はブラウザごとに保存されます。変更後の会計から新しい記録先が使われます。すでに送信待ちの会計は、記録先を元のファイルに戻すと再送できます。商品設定や履歴は端末に保存されるため、GitHub Pages版から切り替える場合は、必要に応じて旧版からExcelを出力してください。

### 記録内容と通信エラー

- 会計ごとに1行で、会計ID、日時（UTCのISO形式）、商品・数量・単価、小計、割引名・率・額、合計、個数を追記します。既存の他のタブには書き込みません。`MitasaiSales` に異なる見出しの表がある場合は停止します。
- 先に端末へ会計を保存してから送信します。通信失敗・タイムアウト時は未送信として保持し、次の会計時、ページ再表示時、オンライン復帰時、または再送ボタンで再試行します。
- 送信結果の応答が失われても、同じ会計IDの再送では重複追記しません。複数端末からの同時書き込みもスクリプトのロックで順番に処理します。同じ記録先を使う全端末に**同じApps Scriptデプロイ**を設定してください。
- 初回設定前や自動記録停止中の履歴は自動送信されません。従来のExcel出力で取り出せます。
- 設定と接続用トークンは端末のローカルストレージに保存します。未送信の会計がある間はブラウザのデータを消さないでください。複数端末ではスプレッドシート上の売上を合算できますが、商品設定・ローカル履歴・Excel出力は端末ごとのままです。
- ネットワーク・Googleアカウント・Apps Scriptの利用制限により送信できない場合は、端末保存とExcel出力を継続できます。応答本文を確認できた場合のみ送信済みとし、`no-cors` の不透明な応答は成功扱いしません。

実装で使用するGoogle公式仕様： [ウェブアプリ](https://developers.google.com/apps-script/guides/web)、[Content Serviceのリダイレクト](https://developers.google.com/apps-script/guides/content)、[Lock Service](https://developers.google.com/apps-script/reference/lock)。

### 開発時の確認

Node.js 18以降で `node --test tests/*.test.cjs` を実行すると、URL検証、通信応答、失敗時の保持と再送、記録先変更、サーバー側の認証・重複排除・明細検証を確認できます。Googleへの実書き込みは初回設定後の接続確認とテスト会計で検証してください。

## 機能概要

- **見やすい UI**: 商品一覧と注文サマリーを並べて表示し、合計金額や割引がひと目で分かります。
- **管理画面**: 商品の追加・価格変更・削除、割引率の追加/変更/削除をブラウザ上で完結できます。フレーバーごとの標準価格は以下の通りで初期登録されています。
  - 500 円: プレーン（塩）
  - 600 円: マヨネーズ / 明太子マヨ / ブラックペッパー / 海苔塩 / 醤油バター
- **100 円引き調整**: 売れ行きに合わせ、管理画面からワンクリックで各フレーバーを 100 円引きにし、ボタン一つで元の価格に戻せます。
- **売上 Excel**: 会計ボタンでデータを蓄積し、必要なときに以下を含むファイルを手動エクスポートできます。
  - 会計ごとの明細 (`SalesLog` シート)
  - 売上合計金額/総数と会計件数 (`Summary` シート)
  - 2 時間ごとの売上個数集計 (`ByTimeSlot` シート)
- **手動エクスポート**: 管理画面の「手動でエクスポート」から、任意のタイミングで最新の売上ファイルを再取得できます。

## データの保持について

- 商品・割引・売上履歴は、ブラウザのローカルストレージに保存されます。
- ブラウザを変更/シークレットモードを使用するとデータは共有されないため、本番利用の端末を固定してください。

## カスタマイズ

アプリはプレーンな HTML/CSS/JavaScript で構成されているため、好みに応じて `styles.css` や `app.js` を編集するだけで見た目や挙動を調整できます。
